## 0. 总览：插件对外的三个 HTTP 面

| # | 面 | 方向 | 说明 |
|---|---|---|---|
| A | `GET {base_url}/generate` | 出站（插件→上游） | 传统 GET 直连。**v2.7.1 起不再是主通道**，只在任务接口返回 404 时兜底 |
| B | `POST {base_url}/api/web/jobs` + `GET {base_url}/api/jobs/{id}` | 出站 | 任务接口，**直连模式的固定首选通道** |
| C | `POST {openai_api_base_url}/v1/images/generations` \| `/v1/images/edits` | 出站 | OpenAI 兼容模式 |
| A2 | `POST {base_url}/api/api/getUser` | 出站 | 余额/额度查询（`/quota`、`/price`） |
| D | `POST 127.0.0.1:{port}/v1/images/generations` \| `/v1/images/edits` | **入站**（插件当服务端） | 本地 OpenAI 兼容代理，供陪伴插件等调用。协议与 C 的请求体兼容 |

出站请求全部走同一个 `aiohttp.ClientSession`（`main.py:1332-1339`）：

```python
self._session = aiohttp.ClientSession(
    timeout=aiohttp.ClientTimeout(total=180),
    trust_env=not self.bypass_system_proxy,
    connector=aiohttp.TCPConnector(force_close=True),
)
```

- `bypass_system_proxy` 默认 `true` → `trust_env=False`，**忽略系统/环境变量代理**。
- `force_close=True` → 不复用 keep-alive 连接，每次请求新建连接。
- Session 级默认超时 180s；各调用点另行传入 `aiohttp.ClientTimeout(total=self.request_timeout)` 覆盖（`request_timeout` 配置，默认 180，钳制 30–600）。
- **未在源码中确认**：任何 `User-Agent`、`Accept`、`Retry-After` 处理；aiohttp 默认值之外没有额外请求头。

## 1. NAI 直连（传统 GET 模式）

### 1.1 base URL 与路径

| 项 | 值 | 出处 |
|---|---|---|
| 默认 base URL | `https://nai.sta1n.cn` | `main.py:115` `IMAGE_GEN_BASE_URL_DEFAULT`；`_conf_schema.json` `base_url.default` |
| 配置键 | `base_url`，仅 `call_mode == "direct"` 时显示 | `_conf_schema.json` |
| 路径 | `/generate` | `main.py:2416`、`main.py:3863` |
| 拼接 | `f"{self.base_url.rstrip('/')}/generate"` — 去掉尾部斜杠后拼接 | 同上 |

### 1.2 调用时机（重要）

直连模式**固定先走任务接口**；只有任务接口返回 **HTTP 404**（旧版自建 Nai2API 无该接口）才回退 GET：

```python
# main.py:3828-3830
# 直连通道固定为任务接口（/api/web/jobs）优先：支持 1-50 步、
# 按「步数 × 画质」档位计价、失败退点；上游无该接口（404，自建
# 旧版 Nai2API）时自动回退 GET 直链（>28 步按 28 路由、基础档计价）。
web_img, web_reason = await self._submit_web_job(...)
...
if web_reason != "web_jobs_unavailable":
    return None, web_reason
```

`web_jobs_unavailable` 只在 `resp.status == 404` 时产生（`main.py:3557-3562`）。

### 1.3 HTTP 方法与认证

- **方法**：`GET`（`self._session.get(url, ...)`，`main.py:3883`／`main.py:2435`）。
- **认证**：**token 放在 query 参数里，参数名 `token`，明文**，没有 header 认证。
- 请求头：源码未设置任何自定义 header，全部为 aiohttp 默认。

> 源码注释明确说明这一点的动机（任务接口则相反）：
> `main.py:3513-3514`：「token 经 POST body 与轮询请求头（x-user-token）传递，不出现在 URL 中。」

**未在源码中确认**：`nocache` 的取值语义（是否接受 0）、上游对未知参数的处理、`tag` 的长度上限。

### 1.5 响应结构与失败形态

**成功**：`HTTP 200`，响应体是**裸图片二进制**（不是 JSON、不是 base64、不是 URL）。

```python
# main.py:3899-3905
img_bytes = await resp.read()
if not img_bytes:
    ...
    return None, "empty_response"
```

插件不做 `Content-Type` 校验，只按字节处理；若前 8 字节等于 PNG magic（`\x89PNG\r\n\x1a\n`）则解析 IHDR 宽高写日志（`main.py:2466-2471`，仅 `_generate_one_custom` 路径）。

**失败**：按状态码区间归类成 reason 字符串（`main.py:3887-3898`）：

| 上游情况 | 插件内部 reason |
|---|---|
| `400 ≤ status < 500` | `"http_4xx"` |
| `500 ≤ status < 600` | `"http_5xx"` |
| 其它非 200 | `"http_other"` |
| 200 但 body 长度 0 | `"empty_response"` |
| 超时（超过 `request_timeout`） | `"timeout"` |
| 其它异常 | `"exception"` |
| 未配 token / 无 session | `"no_token"` / `"no_session"` |

`_generate_one_custom` 路径会把状态码和错误摘要编进 reason，形如 `http_4xx (HTTP 400): <错误正文前 200 字>`（`main.py:2449-2461`）。

GET 通道**没有任何自动重试，也没有任何退避**（对比 §6：重试只实现在 OpenAI 兼容模式）。

## 2. 任务接口模式（直连模式的固定首选通道）

### 2.1 提交 `POST /api/web/jobs`

出处 `main.py:3494-3603`。

**URL**：`f"{base}/api/web/jobs"`，`base = self.base_url.rstrip("/")`（测试断言 `https://nai.example.com/api/web/jobs`，`tests/test_direct_pricing.py:190`）。

**请求头**（`main.py:3554`）：

```
Content-Type: application/json
```

**请求体**（`main.py:3531-3544`，`json=payload`）：

```python
payload = {
    "token": _token,
    "tag": full_prompt,
    "artist": artists or "",
    "model": model,
    "size": size,
    "steps": _steps,
    "scale": scale,
    "cfg": cfg,

```

| 字段 | 类型 | 值域 |
|---|---|---|
| `token` | string | 同 GET 的 `token`（`image_gen_key`）；**body 里明文**，同时轮询时通过 header 传 |
| `tag` | string | 同 GET |
| `artist` | string | 同 GET，空时传 `""` |
| `model` | string | 同 GET |
| `size` | string | 中文分档名，同 GET |
| `steps` | int | `max(1, min(int(steps), 50))` — **钳到 1–50**（`main.py:3530`） |
| `scale` | float | 同 GET |
| `cfg` | float | 同 GET（实例化时已钳 0–1） |
| `sampler` | string | 见 §4.1 |
| `negative` | string | 同 GET |
| `noise_schedule` | string | 见 §4.2 |
| `nocache` | int，恒 `1` | 固定 |

**超时**：`aiohttp.ClientTimeout(total=WEB_JOB_SUBMIT_TIMEOUT)`，`WEB_JOB_SUBMIT_TIMEOUT = 30` 秒（`main.py:342`）。

**可接受的响应状态**：`200` 或 `202`（`main.py:3563`）。

**响应体**（JSON，读 `id` / `status` / `cost`）：

```python

job_id = str(job.get("id") or "")
if not job_id:
    ...
    return None, "invalid_response"
actual_cost = job.get("cost")
logger.info(
    f"{LOG_TAG} [web_job] 任务已入队 | id={job_id} status={job.get('status')} "

```

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `id` | string | **必需**，缺失 → `invalid_response` | 任务 ID，用于轮询 |
| `status` | string | 日志读取 | 提交响应里的取值只用于打日志 |
| `cost` | int | 可选 | 实际扣费点数；缺失时用本地估算值打日志 |

**失败分类**：

| 情况 | 处理 |
|---|---|
| `404` | 返回 `"web_jobs_unavailable"`，**触发 GET 直链兜底** |
| 其它非 200/202 | `http_4xx (HTTP N): <摘要>` / `http_5xx (...)` / `http_other (...)`；摘要优先取错误 JSON 的 `error` 或 `message` 字段（`_summarize_error_body`，`main.py:422-437`） |
| 响应非 JSON | `"invalid_response"` |
| 提交超时（>30s） | `"timeout"` |
| 其它异常 | `"exception"` |

### 2.2 轮询 `GET /api/jobs/{id}`

出处 `main.py:3605-3661`。

```
GET {base}/api/jobs/{job_id}
Header: x-user-token: {token}
Timeout: 15s（WEB_JOB_POLL_REQUEST_TIMEOUT）
Interval: 2s（WEB_JOB_POLL_INTERVAL）
总等待上限: self.request_timeout（默认 180s，配置范围 30–600）
```

```python
# main.py:3611-3613
async with self._session.get(
    f"{base}/api/jobs/{job_id}",
    headers={"x-user-token": _token},
    ...
```

**响应体字段**（JSON）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | 状态机，**只有三个受处理的值**：`"done"` / `"failed"` / 其它（继续轮询） |
| `imageUrl` | string | 仅 `status == "done"` 时读取；**缺失即判 `invalid_response`** |
| `error` | string | 仅 `status == "failed"` 时读取，缺失时日志记 `"上游未返回原因"`，**该字段不影响 reason** |
| `id` | string | 响应里存在，但轮询阶段不再读取 |

```python
# main.py:3629-3646
status = str(job.get("status") or "")
if status == "done":
    image_url = str(job.get("imageUrl") or "")
    if not image_url:
        return None, "invalid_response"
    return await self._download_web_job_image(base, image_url)
if status == "failed":
    error_text = str(job.get("error") or "上游未返回原因")
    logger.warning(... "（点数会自动退回）")
    return None, "web_job_failed"
```

**测试用例确认的完整状态序列**（`tests/test_direct_pricing.py:164-198`）：

```python
poll_bodies=[
    {"id": "job_1", "status": "queued"},
    {"id": "job_1", "status": "running"},
    {"id": "job_1", "status": "done", "imageUrl": "/api/images/img_1/content"},
]
```

→ 即源码中实际出现过的 status 取值为 **`queued` / `running` / `done` / `failed`**。除 `done` 与 `failed` 外全部按「未完成」继续轮询。**未在源码中确认**：是否存在 `pending`、`cancelled` 等其它取值。

**轮询失败容忍**：单次轮询异常或非 200 时 `poll_failures += 1`，**连续 3 次**失败才放弃并返回 `"exception"`；任何一次成功即清零（`main.py:3629-3630`、`3647-3654`）。轮询**没有指数退避**，固定 2 秒间隔。

### 2.3 下载图片

出处 `main.py:3663-3702`。

- URL 拼接规则（`main.py:3668-3671`）：
  - `imageUrl` 以 `http://` / `https://` 开头 → 直接使用；
  - 否则 `f"{base}{'/' + image_url.lstrip('/') if not image_url.startswith('/') else image_url}"` — 相对路径与绝对路径都拼到 `base` 上。
  - 测试断言：`/api/images/img_1/content` → `https://nai.example.com/api/images/img_1/content`。
- **无认证头**（源码里这次 GET 只传了 URL 和超时）。
- 超时 **60 秒**（硬编码 `aiohttp.ClientTimeout(total=60)`）。
- **错误占位图检测**：响应头 `x-error: 1` → 直接判 `"web_job_failed"`，不把错误图当成功归档：

```python
# main.py:3676-3679
# 上游用 x-error:1 标记错误占位图，避免把错误图当成功归档。
if resp.headers.get("x-error") == "1":
    logger.warning(f"{LOG_TAG} [web_job] 图片下载收到错误占位图")
    return None, "web_job_failed"
```

- 成功条件：`status == 200` 且 body 非空 → 返回裸图片字节；否则 `http_4xx (HTTP N)` / `http_5xx (HTTP N)` / `http_other (HTTP N)` / `empty_response` / `timeout` / `exception`。

## 3. OpenAI 兼容模式

### 3.1 端点拼接

出处 `main.py:1629-1646`。`base = self.openai_api_base_url.rstrip("/")`，`target ∈ {"generations", "edits"}`：

| base 形态 | 结果 |
|---|---|

**(b) 契约校正**（`_normalize_openai_size`，`main.py:1591-1627`）：

```python
_OPENAI_MAX_SIDE = 1920
_OPENAI_MAX_AREA = 3686400

    return "1024x1024"

height = max(64, (int(match.group(2)) + 32) // 64 * 64)
while max(width, height) > self._OPENAI_MAX_SIDE and min(width, height) > 64:
    if width >= height: width -= 64
    else:               height -= 64
while width * height > self._OPENAI_MAX_AREA and min(width, height) > 64:
    if width >= height: width -= 64
    else:               height -= 64
```

### 3.10 参考图的编码与预处理

**统一用 Data URI**（`main.py:1912-1925`）：

```python
# Data URI 格式（与文档 §5 参考图示例一致）；MIME 按文件魔数
# 判断，尺寸适配后的字节固定为 PNG，未适配的原图保持自身格式。
for raw in ref_bytes_list:

    elif raw[:4] == b"RIFF" and raw[8:12] == b"WEBP": _mime = "image/webp"
```

## 5. 图片大小处理（精确阈值）

### 5.1 请求尺寸（出站 `size` 字段）的收敛

`_OPENAI_MAX_SIDE = 1920`，`_OPENAI_MAX_AREA = 3686400`（`main.py:1575-1576`）。

- 宽高**向最近 64 倍数取整**：`max(64, (v + 32) // 64 * 64)`（四舍五入到 64 的倍数，不低于 64）。
- 然后循环：**只要 `max(w,h) > 1920` 且 `min(w,h) > 64`**，就把较长边减 64。
- 再循环：**只要 `w*h > 3686400` 且 `min(w,h) > 64`**，就把较长边减 64。
- 无法解析 → `1024x1024`。

> 两个循环都带 `min(width, height) > 64` 保护，所以理论上不会被压到 0；但**当 `min(w,h)` 已经等于 64 时循环不再收敛**，此时会保留超标尺寸。源码未对这种情况做特殊处理。

### 5.2 参考图的缩放（vibe / director）

`is_edit == False` 时用等比缩小（`main.py:1869-1893`）：

```python
def _fit_ref_image(raw_bytes: bytes) -> bytes:
    with Image.open(io.BytesIO(raw_bytes)) as img:
        w, h = img.size
        if is_edit:
            ...  # 见 5.3
        else:
            ratio = min(
                1.0,
                self._OPENAI_MAX_SIDE / max(w, h),
                (self._OPENAI_MAX_AREA / max(1, w * h)) ** 0.5,
            )
            if ratio >= 1.0:
                return raw_bytes
            img = img.resize(
                (max(1, int(w * ratio)), max(1, int(h * ratio))),
                Image.Resampling.LANCZOS,
            )
            logger.info(... f"参考图超限，等比缩小: {w}x{h} -> {img.size[0]}x{img.size[1]}")
```

精确规则：

1. `ratio = min(1.0, 1920 / max(w,h), sqrt(3686400 / (w*h)))` —— 同时满足「最长边 ≤ **1920**」和「面积 ≤ **3686400**」。
2. `ratio >= 1.0` → **原图字节原样返回，不重编码、不放大**。
3. 否则按 `(max(1, int(w*ratio)), max(1, int(h*ratio)))` 缩放，LANCZOS 重采样。
4. 缩放/裁剪后的图 `convert("RGBA" if "A" in img.getbands() else "RGB")` 并**统一另存为 PNG**（`main.py:1894-1897`），因此 Data URI 的 MIME 会是 `image/png`。
5. 单张处理失败（异常）→ **回退用原图字节**，不中断整个请求（`main.py:1904-1908`）。

### 5.3 参考图的裁剪（img2img）

**不是等比缩小，是 `ImageOps.fit` 拉伸/裁剪到目标画布**（`main.py:1872-1877`）：

```python
if is_edit:
    if (w, h) == (target_w, target_h):
        return raw_bytes
    img = ImageOps.fit(img, (target_w, target_h), Image.Resampling.LANCZOS)
```

尺寸已一致时原样返回（不重编码）；否则强制 fit 到 `(target_w, target_h)`（即 §3.5(c) 从 `size` 解析出来的目标分辨率）。源码注释点明原因（`main.py:1850-1854`）：

```
# img2img 要求源图与目标尺寸严格一致，否则上游直接拒绝，且数组仅以
# 第一张作为主输入图（§5.3）；vibe / director 不强制比例，但上游适配
# 器同样按 §10 契约校验参考图（最大边 1920、面积 3686400），超限会报
# "image dimensions exceed the maximum allowed size"，因此超限图片先
# 等比缩小（不放大、不重编码合规图）。
```

## 6. 重试策略

**只实现在 OpenAI 兼容模式**（`_openai_generate`，`main.py:2141-2194`）。直连 GET 与任务接口**均无重试**。

### 6.1 常量

### 6.2 重试轮次与退避

```python
# main.py:2144-2154
max_attempts = self.openai_max_retries + 1
for attempt in range(1, max_attempts + 1):
    if attempt > 1:
        delay = OPENAI_RETRY_DELAYS[min(attempt - 2, len(OPENAI_RETRY_DELAYS) - 1)]
        logger.info(... f"第 {attempt - 1}/{self.openai_max_retries} 次重试，等待 {delay:g}s ...")

```

| 重试次数配置 | 总尝试次数 | 实际等待序列 |
|---|---|---|
| 0 | 1 | — |
| 1 | 2 | 2s |
| **2（默认）** | **3** | **2s, 4s** |
| 3 | 4 | 2s, 4s, 8s |

### 6.3 判定逻辑

```python

    # 错误文案明确提示"请稍后重试"时同样按可重试处理。

    break
```
